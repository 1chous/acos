Последовательная имитационная модель группы лифтов: консольное приложение
на C, один процесс и один поток, дискретное модельное время в тактах.

## Сборка

```
make
```

Собирается `build/elevator`. Требуется компилятор C17 и `make`.
Программа использует только libc и системные вызовы POSIX.2008.

```
make clean
```

## Запуск

Со сценарием из файла:

```
./build/elevator --config data/default.conf
```

С параметрами из командной строки (они перекрывают файл):

```
./build/elevator --config data/default.conf --floors 20 --strategy fcfs
```

Без схемы здания, сплошной лентой событий — удобно для скриптов и
перенаправления в файл:

```
./build/elevator --plain --delay-ms 0 --seed 42
```

Полный список параметров:

```
./build/elevator --help
```

## Завершение

Программа останавливается в трёх случаях: доставлены все пассажиры,
исчерпан лимит тактов `--max-ticks`, либо получен сигнал SIGINT (Ctrl-C)
или SIGTERM. В любом из трёх случаев выводится итоговая статистика и
состояние незакрытых заявок.

Код возврата: 0 — норма, 1 — ошибка в параметрах, 2 — в ходе работы был
нарушен инвариант модели (такого быть не должно).

## Состав

```
src/elevator.h   типы и объявления
src/config.c     параметры: умолчания, конфиг-файл, аргументы
src/sim.c        модель: пассажиры, вызовы, диспетчер, кабины, инварианты
src/output.c     схема здания, лента событий, журнал, статистика
src/main.c       сигналы и главный цикл
data/            сценарии, они же тестовые наборы данных
tests/           скрипт прогона тестов
```

## Сценарии в data/

| Файл | Что проверяет |
|------|---------------|
| `default.conf` | базовый случай: 12 этажей, 3 лифта, вместимость 6 |
| `small.conf` | 5 этажей и один лифт, всё видно глазами |
| `rush-hour.conf` | утренний час пик: 16 этажей, 4 лифта, плотный поток |
| `crowded.conf` | вместимость 1, почти каждый вызов приходится перевыставлять |
| `slow-doors.conf` | те же 12 этажей, но медленные двери и посадка, стратегия fcfs |

## Тесты

```
./tests/run-tests.sh
```

Скрипт пересобирает проект и прогоняет 30 проверок: сборка без
предупреждений, отказ на неверных параметрах, все сценарии из `data/`,
обе стратегии, краевые случаи, воспроизводимость по seed, совпадение
журнала с экраном, обработка SIGINT и 60 случайных конфигураций здания.
Возвращает 0, только если прошли все.

## Журнал

По умолчанию пишется в `elevator.log` рядом с местом запуска, путь
меняется параметром `--log`. В журнал попадают шапка с параметрами
запуска, все события модели и итоговая статистика.

Один и тот же `--seed` даёт побайтово одинаковый журнал: генератор
случайных чисел в программе свой, а не библиотечный.
