Многопоточная имитационная модель группы лифтов. Каждая сущность с
поведением — отдельный поток: пассажиры, кабины, диспетчер. Потоки
работают с общим состоянием под мьютексом и будят друг друга сигналами.

## Сборка

```
make
```

Собираются **два исполняемых файла из одного набора исходников**:

| Файл | Чем потоки обмениваются сигналами |
|------|-----------------------------------|
| `build/elevator-sem` | POSIX-семафоры |
| `build/elevator-cond` | условные переменные |

Отличается только один файл: `src/sync_sem.c` против `src/sync_cond.c`.
Модель, вывод и разбор параметров общие.

Требуется компилятор C17 и `make`. Используются libc, системные вызовы
POSIX.2008 и pthread.

```
make clean
```

## Запуск

Со сценарием из файла:

```
./build/elevator-sem --config data/default.conf
```

С параметрами из командной строки (они перекрывают файл):

```
./build/elevator-sem --config data/default.conf --floors 20 --strategy fcfs
```

Без схемы здания, сплошной лентой событий:

```
./build/elevator-cond --plain --passengers 20 --seed 42
```

Полный список параметров:

```
./build/elevator-sem --help
```

## Завершение

Четыре способа, все приводят к выводу статистики и состояния незакрытых
заявок:

| Способ | Что происходит |
|--------|----------------|
| все пассажиры доставлены | штатное завершение |
| `--max-seconds N` | остановка по истечении времени |
| `Ctrl-C` (SIGINT) или SIGTERM | прерывание пользователем |
| `kill -USR1 <pid>` | перестать впускать новых пассажиров и довезти тех, кто в здании |

Код возврата: 0 — норма, 1 — ошибка в параметрах, 2 — во время работы
был нарушен инвариант модели.

## Состав

```
src/elevator.h    типы модели и объявления
src/config.c      параметры: умолчания, конфиг-файл, аргументы
src/sim.c         потоки пассажиров, кабин и диспетчера, инварианты
src/output.c      схема здания, лента событий, журнал, статистика
src/main.c        сигналы и главный цикл
src/sync_sem.c    сигналы между потоками на семафорах
src/sync_cond.c   то же самое на условных переменных
data/             сценарии, они же тестовые наборы данных
tests/            скрипт прогона тестов
```

## Сценарии в data/

| Файл | Что проверяет |
|------|---------------|
| `default.conf` | базовый случай: 12 этажей, 3 лифта, вместимость 6 |
| `small.conf` | 5 этажей и один лифт, всё видно глазами |
| `rush-hour.conf` | утренний час пик: 16 этажей, 4 лифта, плотный поток |
| `crowded.conf` | вместимость 1, почти каждый вызов приходится перевыставлять |
| `slow-doors.conf` | те же 12 этажей, но медленные двери и посадка, стратегия fcfs |

## Тесты

```
./tests/run-tests.sh
```

38 проверок, обе сборки. Скрипт пересобирает проект и проверяет: сборку
без предупреждений, отказ на семи вариантах неверного ввода, все пять
сценариев на обеих сборках, обе стратегии, краевые случаи, совпадение
журнала с экраном, обработку SIGINT и SIGUSR1, 30 случайных конфигураций
здания на каждую сборку и отсутствие гонок данных под ThreadSanitizer.
Возвращает 0, только если прошли все.

У макоси нет команды `timeout`, а основной вид отказа в многопоточной
программе — зависание, поэтому в скрипте есть собственный сторожевой
таймер: каждый прогон снимается принудительно, если не уложился в срок.

## Журнал

Пишется в `elevator.log` рядом с местом запуска, путь меняется
параметром `--log`. Содержит шапку с параметрами, все события модели и
итоговую статистику. События в журнале и на экране совпадают построчно.
